# Findings

A finding is a concise answer supported by identifiable evidence. It must never be stronger than its evidence. There are no findings yet; do not populate this directory with invented results.

For each finding, record:

- **Question:** Research question link and specific claim assessed.
- **Evidence:** Experiments, dataset versions, analyses and/or literature; distinguish physical observations, synthetic tests and qualitative feedback.
- **Result:** Observations, effect/uncertainty where defensible, failures and inconclusive outcomes.
- **Confidence:** Level and rationale tied to validity, precision and scope, not visual polish.
- **Limitations:** Confounders, missing evidence, device/environment/profile/endpoint scope and selection effects.
- **Replication status:** Not replicated, repeated under stated conditions, or independently replicated; identify supporting runs.
- **Product implication:** What this supports, does not support, or suggests investigating.
- **Follow-up needed:** The smallest useful next test or unresolved question.

Link [decisions](../decisions/README.md) without implying implementation approval. Update or supersede findings transparently when evidence changes. Software acceptance and replay success must not become claims of spatial repeatability, network improvement or broad device support.
