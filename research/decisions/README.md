# Research-informed decisions

Record an important choice when research affects what OMANII does, communicates or tests next. Use the [template](DECISION-TEMPLATE.md); do not create decisions just to populate the directory.

Keep the chain short: question → evidence/finding → alternatives → choice and reason → implementation/task, if any. Untested assumptions can inform provisional proposals, but retain low confidence and a revisit condition.

A visual choice such as showing uncertain spatial boundaries as uncertain may merit evaluation. An example is not a decision or evidence that users understand it; the template has no completed example.

These records explain reasoning, not replace [PRODUCT.md](../../PRODUCT.md), [ARCHITECTURE.md](../../ARCHITECTURE.md), [ADRs](../../docs/adr/) or the [promotion contract](../../docs/research/EXPERIMENTS.md). Mark choices proposed until the appropriate owner approves them; link required approval/ADR/task. Francis retains the authorities in [AGENTS.md](../../AGENTS.md).

Status should distinguish proposed, approved, rejected and superseded choices. Use the actual decision date, name the owner where useful and preserve earlier reasoning when superseding. Do not create a shadow architecture or imply research logs grant implementation authority.
